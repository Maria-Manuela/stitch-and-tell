You are building "Stitch & Tell", a bilingual (English + Danish) web app where
people turn a photo, or their own design, into a personalized crochet pattern.

BRAND
- Name: Stitch & Tell
- Tagline EN: "Don't just follow a pattern. Make it personal."
- Tagline DA: "Drøm det. Design det. Hækl det."
- Secondary DA line: "Din idé. Dit mønster. Dit håndværk."
- Treat the taglines as starting points, easy to change in the translation files.

DESIGN
- Clean, modern, Scandinavian minimal. Lots of white space, calm neutral palette (off-white background, warm grey text), ONE soft accent color.
- Let the user's pattern colors be the visual hero. UI chrome stays quiet.
- Mobile-first, responsive, large touch targets. Easy to use for non-technical hobbyists: one clear action per screen, plain language, no jargon.
- Accessibility: WCAG AA contrast, full keyboard navigation, visible focus states, aria labels, prefers-reduced-motion respected. Pattern charts must work for color-blind users: every color gets a unique SYMBOL and a letter, with a toggle between "colors", "symbols", and "both".

STACK
- Next.js (App Router) + TypeScript + Tailwind + shadcn/ui
- Supabase (Auth with magic link/email OTP, Postgres with Row Level Security,
  Storage), deployed on Vercel
- next-intl for i18n (en, da). NO hardcoded UI strings; everything in
  translation files.
- Cloudflare Turnstile on sign-up and generate actions
- Stripe is NOT needed now, but architecture must be ready (see PLANS)

CORE PRINCIPLE (very important)
- Pattern grids are NEVER generated by an image-generation AI. The grid is
  produced by deterministic code: crop, resize to a stitch grid, reduce to
  exactly N colors, then render the chart programmatically as SVG/canvas.
  Squares are always perfect and the number of colors is never exceeded.
- Row-by-row written instructions are generated by code (never by an LLM), so counts are always correct.
- Image processing runs in the browser. Original photos are never stored unless explicitly required. Store only the small pattern data.
- Keep the engine in pure, framework-independent TypeScript modules under/lib/pattern so it is testable and reusable (converter, builder, store).

USER-FACING SETTINGS (global, saved to profile if logged in, otherwise local)
- Language: English / Dansk
- Handedness: Right-handed / Left-handed (see HANDEDNESS)
- Terminology: US / UK / Dansk stitch names
- Units: cm / inches

HANDEDNESS
- Right-handed: working flat in rows, odd rows are read right-to-left and even rows left-to-right. Left-handed: mirrored (odd rows left-to-right, even rows right-to-left). The chart shows an arrow and row number on the correct side for each row, and written instructions say which direction to work.
- Changing handedness must instantly re-render chart and instructions.
  Handedness NEVER changes the pattern data, only how it is displayed.

PATTERN DATA MODEL (single format used everywhere)
- id, title, technique ('tapestry' | 'c2c' | 'graphghan'), width, height (stitches), palette [{id, hex, name, symbol}], grid (2D array of palette ids), settings used, createdBy, visibility ('private' | 'pending' | 'public'), source ('converter' | 'builder' | 'curated'), price (number, default 0), createdAt.

TECHNIQUE RULES
- tapestry: carrying colors, single crochet. Warn when a row uses more than 2 colors and when a color float is longer than ~6 stitches.
- c2c: corner-to-corner. Number diagonals, instructions as blocks per diagonal.
- graphghan: standard row-by-row single crochet color chart; show color-change counts per row.

LIMITS (defaults, kept in ONE config file, never hardcoded in components)
- Colors: 3 to 6 (tapestry recommended 2 to 4, show a hint)
- Max grid: 100 x 100 stitches. Min grid: 10 x 10.

PLANS / ENTITLEMENTS (build now, only the Free plan is active)
- Create a plans config and an entitlements helper, e.g.
  getEntitlements(user) -> { patternsPerWeek, maxColors, maxGrid, pdfBranding, canSavePrivate, ... }.
- Free: 1 generated-and-saved pattern per week, limits above, small
  "Made with Stitch & Tell" footer on PDF.
- All limit checks are enforced SERVER-SIDE (Supabase function or route handler), never only in the browser.
- Future plans (do NOT implement now, but do not block): credit packs / timed passes ("rental"), and a Pro subscription via Stripe.

PRIVACY AND SAFETY
- GDPR-aware (Denmark/EU): consent banner, privacy policy, terms, account and data deletion, data minimization. Public sharing is OPT-IN only.
- Validate uploads (type: jpg/png/webp, max 10 MB), strip EXIF metadata,rate-limit, never expose service-role keys to the client.
- Enable Row Level Security on every table; users can only access their own private data.
